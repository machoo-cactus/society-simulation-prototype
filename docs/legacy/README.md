# Legacy Documentation Archive

Historical documents preserve provenance. They describe the design believed,
proposed, or implemented at their recorded time; old paths, schemas, routes,
tools, UI stacks, and compatibility behavior are intentionally not rewritten
as current instructions.

Start with [Development History](DEVELOPMENT_HISTORY.md) for a compressed
chronology. Use [current documentation](../README.md) for all implementation and
operating guidance.

## Archive rules

- Add only minimal banners or metadata to old records.
- Explain corrections in this index or development history, not by rewriting
  the historical body.
- Current docs may link here for rationale; legacy docs must not become the
  source of current commands or contracts.
